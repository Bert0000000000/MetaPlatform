01 / 平台介绍

把业务语言变成协作基础

业务团队需要看清问题，数据团队需要统一口径，应用与 AI 团队需要可靠上下文。MetaPlatform 用一层共享的业务语义，把这些工作连接起来。

01

看懂同一门业务

把不同系统的字段组织成客户、订单与合同，明确对象之间的关系和可执行动作，减少反复解释与口径分歧。

02

让 AI 带着上下文工作

把当前对象、相关知识和授权工具带入任务，让 Agent 的分析与建议有业务依据，便于团队判断与确认。

03

把建议接到业务行动

在应用中承接信息、流程与人工决策，让经授权的动作回到业务对象，留下可查看的结果和操作记录。

03 / 业务场景

从一笔订单，到一次有依据的决策

1.1 优先打通订单审核：让运营与审核人员在一个应用中看清客户、订单及相关依据，再确认下一步动作。

1.1 首条业务链 · 开发中

订单审核工作台

起点是已有订单与客户数据。目标是交付关联对象、审核界面、可确认的建议，以及执行后的回执。

进入平台

  1. 接入数据与建立模型

    连接数据表或 CSV，将字段映射到订单与客户，定义并建立对象关联。

  2. 在应用中查看上下文

    绑定订单应用，查看同一笔订单、客户信息与相关知识，理解审核依据。

  3. 形成建议，由人决策

    Agent 使用授权工具提出动作建议；业务人员查看影响并作出确认。

  4. 执行动作，查看回执

    经确认的动作更新业务状态，返回结果与记录，便于追踪和后续处理。

场景示例 · 非客户案例

合同与客户信息梳理

客户团队从分散的合同与客户资料出发，组织关联对象和知识，辅助核对约定、识别待处理事项。

场景示例 · 非客户案例

业务目标与任务协作

业务负责人提出目标，Agent 团队结合知识与工具组织分析，将建议和交付物带回人工决策流程。

06 / 常见问题

开始之前

什么是业务本体？

它是一套团队共享的业务描述。以订单为例，不仅有金额、状态等属性，还有与客户、合同的关系，以及审核等动作。模型映射把数据字段与这些概念连接起来，应用与 Agent 因而可以使用同一套业务含义。

如何开始使用 MetaPlatform？

点击“进入平台”，使用已有平台账号登录工作区，再根据授权使用数据、模型与应用入口。官网公开可读；具体功能与数据需要相应的部署配置和工作区权限。1.1.0 当前仍在开发中。

Agent 可以直接执行业务动作吗？

Agent 的访问和工具调用受身份、租户与授权限制。需要人工确认的动作先形成建议，由业务人员确认后执行；外部客户端的接入与撤销能力会按版本规划继续完善。

在哪里了解更新与后续版本？

产品更新记录已完成的产品改进；版本规划说明当前开发目标和未来方向。开发进展与版本发布分别说明，规划中的能力不会作为已发布功能承诺。
