02 · 本体引擎

语义统一,
而非模型拼接。

Ontology 本体引擎是 Mate Platform 的语义心脏。 概念、对象、动作、事件、版本在图数据库中以同一张图维护, 被低代码、Agent、RAG、Action 治理四个上层共用。 它把"业务事实"变成"可被任意子系统检索的图节点", 让 AI 真正基于业务而非幻觉作答。

四层架构 · 自下而上读取,自上而下治理

本体引擎以 L1 模型层 定义语义, L2 图谱层 存储关系, L3 推理层 包装上下文, L4 动作层 治理回写。 写入语义集中在底部 ETL 与顶部 Action 两条路径, 其它层均为只读计算。

L1
模型层 · Model OWL/TBox: 类、属性、关系、约束;事实声明的单一来源
JSON Schema Postgres Version
L2
图谱层 · Graph ABox: 概念图、对象图、动作图;关系推理与跨域联接
Neo4j 5.x Cypher GraphQL
L3
推理层 · Reasoning Context Envelope、签名校验;规则与 LLM 协同
Drools 8 LangGraph Redis · TTL
L4
动作层 · Action ActionPolicy 治理、Approve/Reject、幂等执行、审计可追溯
Flowable 8 OTel Kafka 审计
03 · 核心能力

一底座,五能力。

围绕 Ontology 引擎构建的五大核心能力, 既可独立使用,又彼此咬合。

低代码应用构建 ↗

表单设计器、流程设计器、版本管理、灰度发布一应俱全。 BPMN 2.0 工作流引擎承接企业级审批, 业务专家可独立完成 80% 应用交付。

AI Agent 编排 ↗

LangGraph 驱动的多 Agent 协作,每 Thread 独立 K8s Sandbox。 Ontology Context Envelope 给 Agent 不可变业务上下文, 让 LLM 真正基于事实而非幻觉。

LangGraph Code Mode K8s Sandbox Sub-Agent

RAGFlow + LightRAG 双引擎。4 切片策略、向量检索、引用回溯, 全部走 Ontology 过滤,租户级隔离。

Milvus RAGFlow 本体过滤 引用回溯

MCP / A2A 协议 ↗

标准化工具调用与 Agent 互联。外部系统 ACL Client 唯一接入, Server/Client 双向审计,跨域 Agent 路由安全可追溯。
