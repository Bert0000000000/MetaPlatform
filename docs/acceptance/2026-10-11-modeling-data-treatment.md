# Excel 数据处理与合格子集同步：本地验收

日期：2026-10-11。依据：[实施计划](../superpowers/plans/2026-10-11-modeling-data-treatment.md)、[ADR-0083](../active/decisions/ADR-0083-data-driven-modeling-phase1.md)。本记录为本地工程验收，不代替主干 CI、生产部署或业务验收。

## 已实现链路

从数据建模第五步执行数据检查，显示合格对象/关系数量和暂缓范围。AI 分析以持久化异步任务运行，最多分析三十组冲突；只允许提出来源中实际存在的非身份属性值，附修复依据，不能编造、任意聚合或修改已发布身份。用户选择并确认修复组后保存修复审计，重新全量校验。没有可靠依据的问题保持暂缓。

确认修复复用 Draft.instanceEdits，通过来源局部有效草稿计算，不改写 Excel 或已发布模型。候选变化使旧修复及方案失效。身份、粒度调整继续遵循原生建模与迁移流程。

用户明确确认暂缓范围后，提交当前检查哈希，后台重算合格子图并校验原生基线。空身份暂缓来源行；同身份属性冲突、已知身份的类型错误、替代唯一键冲突和父子身份重叠暂缓完整身份组；基数冲突暂缓相关关系，暂缓端点不写关联。结构、审核、映射及非法修订错误仍阻断。

写入复用平台背挂数据源、原生对象 upsert 与关系接口，保留手工覆盖层优先和 append-upsert 语义。暂缓不会删除平台已有实例或旧关系。暂存表在每个类型的事务内替换为本次合格执行快照，防止旧失败批次被原生扫描再次导入；全暂缓类型清空受控暂存并跳过同步。原生 delete_missing=false，清空暂存不会删除正式对象。租户级 Excel 同步锁串行化共享暂存的跨来源写入。

页面保留修复前后值、来源行、确认审计、检查和同步局部反馈。暂缓清单界面最多显示一百组，完整明细通过检查哈希约束的 CSV 导出，单元格公式转义。

## 实际验证

- 后端编译器、治理与 Copilot 回归：218 passed。
- 独立 PostgreSQL 建模集成：32 passed；最后补充的租户锁竞争断言单独运行：1 passed，31 deselected。覆盖过期确认、隔离、部分同步及旧失败暂存不重新进入。
- 平台必需原生 PostgreSQL 六组门禁：123 passed、0 skipped。
- 从数据建模前端：54 passed；生产类型检查及构建通过，保留既有 chunk-size 提示。
- OpenAPI YAML 解析、差异空白检查通过。
- 主 ONT 服务已重启加载最终代码，三个新增 ONT 接口和 Copilot 修复接口可在运行服务 OpenAPI 中读取；前端网关读取八个现有来源正常。独立浏览器测试服务已停止。
- 最终代码的隔离浏览器闭环：真实前端、真实后端与独立 PostgreSQL，受控 AI 响应。方案初始不修改数据；确认一组后重新检查，显式确认子集，实际同步四个对象和两条关系，暂缓一行；刷新后结果保留，CSV 导出成功，点击“查看实例”进入平台原生对象浏览并看到确认后的 999。

证据在本地 `.cache/local-runtime/`：`sync-integration.xml`、`treatment-lock-focused.xml`、`data-treatment-native.xml`、`data-treatment-native.collection.json`、`data-treatment-frontend-tests.json`、`treatment-proposal-desktop.png`、`treatment-result-desktop.png`、`treatment-mobile.png`、`treatment-object-browser.png`。AI 响应受控验证协议及确认链路，不证明真实模型对业务冲突的判断质量。

## 业务数据边界

未调用用户业务来源的 AI 修复、确认或同步，未改写业务 Excel、模型及实例。只读编译当前来源得到 3727 个合格对象和 4931 条合格关系，9393 个不同来源行涉及暂缓；这是评估结果，不是已入库数量。多条错误可能涉及同一行，错误次数不能直接当作待修改记录数。

无法从来源确定的缺失身份、含糊版本或真实业务冲突仍需暂缓，AI 不保证全自动消除。使用顺序：刷新页面 → 第五步检查数据 → 可选 AI 分析 → 选择并确认修复 → 核对暂缓范围 → 同步合格数据 → 查看实例。
