# 候选审核工作区整理

按用户批准的“紧凑总览、分类列表、详情抽屉”方案组织审核。对象类型、业务关系、数据映射使用同一列表模式，支持搜索和审核状态筛选；对象与关系继续使用原有批量审核规则，人工确认、身份和基数依据、发布锁定及修订失效机制保持原有行为。

使用平台共享 SheetDetail、Semi UI 与现有主题变量，详情仍采用已有表单编辑逻辑。默认只展示列表，概念层次、语义与说明按需打开。发布过的候选显示已有发布结果与锁定说明，底部可进入发布结果；未发布候选以校验预览为主操作。所有更改保留在草稿，列表或抽屉交互不直接写入正式本体。

- 从数据建模模块 Vitest 回归：9 个测试文件、35 项测试全部通过，覆盖列表搜索、键盘分类切换、审核限制、详情编辑、保存冲突和发布锁定等行为。
- 前端类型检查及生产构建通过；构建仅有现有的大分包提示。
- 使用实际来源进行桌面及 390px 窄屏浏览检查，验证三个分类、详情抽屉和列表横向滚动。验证过程未写入草稿，来源仍为修订 11，已成功的生成任务未改变。
- git diff --check 通过。

本地验证截图与测试报告保存在忽略目录 .cache/local-runtime 下：review-list.png、review-drawer.png、review-mobile.png、review-suite.json。

## 批量审核弹窗样式修正

对象及关系批量审核弹窗统一使用最大 960px 的响应式宽度并居中。规则与依据占据主要列宽，候选名称、复选框和状态使用固定列宽；表头吸顶、列表独立滚动，标题与确认操作保留在可视区域。说明文字与选择数量简化为单独的提示行，状态使用平台 Tag。

验证：前端类型检查、生产构建、FromDataPage 的 20 项回归测试及 git diff --check 通过。浏览器检查两个分类和 390px 窄屏，弹窗均处于视口内。为展示已确认来源的审核弹窗，仅在验证浏览器内拦截 GET 响应，将候选 accepted 标记设为 false；未修改服务端数据，草稿写入次数为 0。截图为 .cache/local-runtime/review-batch-desktop.png 与 review-batch-mobile.png。

## 子类身份修正入口

子类身份与父类不一致时，详情提供“沿用父类身份”。应用前必须确认每份子类映射中的父类身份对应来源列；单字段身份使用原身份绑定作建议，复合身份不猜测字段对应。应用后保留原属性，补齐父类属性及身份，使子类和后代身份回到待确认，并取消相关映射、关系与语义确认。原有关联字段保留，用户需重新核对。已发布候选禁用此操作，未自动修改任何用户草稿。

验证：38 项模块测试通过，覆盖修正后的身份一致性、映射保留与补充、确认失效、复合身份不完整时禁止应用，以及已发布锁定。类型检查、生产构建和 git diff --check 通过。实际最新来源中打开产成品的修正弹窗，正确建议“物料编码 ← 产品编码”，未点击应用、未写入草稿。截图：.cache/local-runtime/parent-identity-repair.png。
