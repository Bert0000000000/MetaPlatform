## Known issues / lessons learned

1. **`docker buildx` zombie process**: If `docker build` is killed mid-build
   (Ctrl-C, PowerShell 240s timeout, etc.), the `docker-buildx.exe`
   process can linger with 0% CPU. Symptom: subsequent builds hang at
   `naming to` step. Fix: `Get-Process docker-buildx | Stop-Process -Force`.

2. **PowerShell 240s command timeout**: The shell tool kills long-running
   `docker build` commands after 240 seconds. Build a single `mate-tech-*`
   image takes 90-180 seconds (uv sync dominates), so a build that gets
   killed at 240s is usually past uv sync but before `naming to`. The image
   is lost. **Solution**: run builds in detached mode (Start-Process) or
   in an external PowerShell terminal you control.

3. **`.pytest_cache` ACL lock**: When pytest was running while Docker was
   uninstalled, `.pytest_cache/` directories got ACL locks that block
   buildkit's `COPY packages/`. Solution: copy `mate-platform-backend/` to
   `.tmp-build-context/` excluding `.pytest_cache/__pycache__/.venv/...`,
   then point compose at the filtered context via `docker-compose.override.yml`.

4. **Network instability to docker.io/quay.io/cloudfront**: Without
   mirrors, ~50% of pulls hit EOF on large blobs. 7-mirror config in
   `~/.docker/daemon.json` fixed this.

5. **`.wslconfig dataDirectory` does NOT affect docker-desktop/data**: A
   common misconfiguration. The correct way to move Docker's disk image
   is via Docker Desktop GUI: Settings → Resources → Advanced →
   Disk image location. (Or via `wsl --import` after uninstall, see
   `scripts/wsl2-recover-distros.sh`.)
