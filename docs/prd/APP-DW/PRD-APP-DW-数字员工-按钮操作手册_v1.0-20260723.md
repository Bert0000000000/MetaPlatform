## 1. 「创建任务」按钮（FR-DW-3.4.1）

**触发位置**：任务管理 `/agents/{agentId}/tasks` 右上角「创建任务」。

**操作流程**：

1. 用户点击「创建任务」 → 弹出"创建任务"向导（3 步）
2. **第 1 步：基础信息**

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|------|------|------|---------|------|
| 任务名称 | String(2-50) | 是 | 唯一 | - |
| 任务编码 | String[a-z0-9-]{3,30} | 是 | 唯一 | - |
| 任务描述 | Text(10-500) | 是 | 至少 10 字 | - |
| 优先级 | Enum | 是 | LOW/MEDIUM/HIGH/URGENT | 默认 MEDIUM |
| 截止时间 | DateTime | 否 | > 当前时间 | - |
| 标签 | Array[String] | 否 | 最多 5 个 | - |

3. **第 2 步：执行参数**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 输入参数 | JSON | 是 | 任务输入数据结构 |
| 期望输出 | JSON | 否 | 用于后续评估 |
| 触发方式 | Enum | 是 | 手动/API/定时/事件 |
| 触发配置 | JSON | 条件 | 触发方式≠手动时必填 |

4. **第 3 步：执行人**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 负责人 | Ref | 是 | 用户/数字员工 |
| 协作人 | Array[Ref] | 否 | - |
| 通知规则 | Multi | 否 | 完成/失败/超时 |

5. 用户点击「创建任务」 → 写入 `task_definition` 表 → 自动跳转到任务详情

## 2. 「发起知识提炼」按钮（FR-DW-3.3.1）

**触发位置**：知识提炼 `/agents/knowledge` → 「发起提炼」。

**操作流程**：

1. 用户点击「发起提炼」 → 弹出"知识提炼向导"（4 步）
2. **第 1 步：选择源**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 源类型 | Enum | 是 | 文档/对话/流程/事件/外部 |
| 源选择 | Ref | 是 | 根据源类型联动 |
| 知识库 | Ref | 是 | 写入目标 KB |

3. **第 2 步：选择数字员工**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 提炼 Agent | Ref | 是 | 至少需要 1 个 |
| 协同 Agent | Array[Ref] | 否 | 多 Agent 协作 |
| 提炼深度 | Enum | 是 | 摘要/要点/完整提取 |

4. **第 3 步：Ontology 映射**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 关联 Ontology | Ref | 否 | 概念抽取目标 |
| 自动创建概念 | Boolean | 是 | 默认 false |
| 置信度阈值 | Float(0-1) | 是 | 默认 0.7 |

5. **第 4 步：审核与发布**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 审核人 | Ref | 是 | - |
| 自动审核 | Boolean | 否 | 高置信度自动通过 |
| 发布时机 | Enum | 是 | 审核后/立即/定时 |

6. 用户点击「开始提炼」 → 异步执行 → 进度条显示

## 3. 「发起多员工协作」按钮（FR-DW-3.7.1）

**触发位置**：协作中心 → 「发起协作」。

**操作流程**：

1. 用户点击「发起协作」 → 弹出"多员工协作配置"对话框
2. 用户填写：

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|---------|
| 协作名称 | String(2-50) | 是 | 唯一 |
| 目标描述 | Text(10-500) | 是 | - |
| 参与员工 | Array[Ref] | 是 | 至少 2 个 |
| 协调员 | Ref | 是 | 负责调度 |
| 协作模式 | Enum | 是 | 串行/并行/混合 |
| 通信协议 | Enum | 是 | A2A/MCP |
| 超时 | Integer(s) | 是 | 默认 600 |

3. 用户配置每个员工的：

| 员工字段 | 说明 |
|---------|------|
| 输入 | 该员工接收的数据 |
| 输出 | 该员工产出的数据 |
| 触发条件 | 上游输出到达时 |
| 异常处理 | 失败时降级/重试/跳过 |

4. 用户点击「创建协作」 → 写入 `collaboration_session` 表 → 生成协作流程图

## 4. 「创建评价指标」按钮（FR-DW-3.6.1）

**触发位置**：效果评估 → 「评价指标」 → 「新建指标」。

**操作流程**：

1. 用户点击「新建指标」 → 弹出"评价指标"对话框
2. 用户填写：

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|---------|
| 指标名称 | String(2-50) | 是 | 唯一 |
| 指标类型 | Enum | 是 | 准确率/响应时间/用户满意度/任务完成率 |
| 计算公式 | Text | 是 | 支持变量引用 {{taskId}} |
| 目标值 | Float | 是 | - |
| 阈值 | JSON | 否 | {warning: 0.7, error: 0.5} |
| 评估频率 | Enum | 是 | 实时/每小时/每天 |
| 关联任务 | Array[Ref] | 否 | 限定评估范围 |

3. 用户点击「保存」 → 写入 `eval_metric` 表

## 5. 「发起版本对比」按钮（FR-DW-3.5.2）

**触发位置**：数字员工详情 → 「版本」 → 「对比版本」。

**操作流程**：

1. 用户选择两个版本（多选下拉），点击「对比版本」
2. 系统跳转到对比视图（左右并排）：

| 对比维度 | 展示 |
|---------|------|
| 配置差异 | 提示词、参数、能力声明 |
| 性能差异 | 响应时间、成功率 |
| 任务执行差异 | 并排展示同一任务在两版本下的输出 |
| 评价指标差异 | 折线图对比 |

3. 用户可点击「采纳此版本」 → 写入 `version_adoption_log`

## 6. 「启用/停用」按钮（FR-DW-3.1.5）

**触发位置**：数字员工列表行 → 「启用/停用」切换。

**操作流程**：

1. 用户点击「停用」 → 弹出二次确认
2. 用户确认后，状态变化：

| 当前状态 | 操作 | 新状态 | 副作用 |
|---------|------|--------|--------|
| ENABLED | 停用 | DISABLED | 停止接收 A2A 调用 + 工作流触发 |
| DISABLED | 启用 | ENABLED | 重新注册到 Nacos + 恢复调度 |
| RUNNING | 暂停 | PAUSED | 当前任务完成后停止 |
| FAILED | 重启 | ENABLED | 重新加载 + 健康检查 |

3. 状态变更触发审计日志

## 7. 「配置测试用例」按钮（FR-DW-3.6.3）

**触发位置**：效果评估 → 「测试用例」 → 「新建用例」。

**操作流程**：

1. 用户点击「新建用例」 → 弹出"测试用例"对话框
2. 用户填写：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 用例名称 | String(2-50) | 是 | - |
| 测试类型 | Enum | 是 | 单元/集成/回归/冒烟 |
| 输入参数 | JSON | 是 | - |
| 期望输出 | JSON | 是 | 用于自动对比 |
| 评估指标 | Array[Ref] | 是 | 至少 1 个 |
| 超时 | Integer(s) | 否 | 默认 30 |

3. 用户点击「保存」 → 写入 `test_case` 表
4. 用户点击「执行」 → 异步执行 → 显示通过/失败

## 8. 「批量导入」按钮（FR-DW-3.1.6）

**触发位置**：数字员工列表 → 「批量操作」 → 「批量导入」。

**操作流程**：

1. 用户点击「批量导入」 → 弹出"批量导入向导"
2. **第 1 步：下载模板**

| 字段 | 内容 |
|------|------|
| Excel 模板 | `name, code, type, description, capabilities, prompt, model` |

3. **第 2 步：上传文件**

| 字段 | 说明 |
|------|------|
| 支持格式 | .xlsx, .csv |
| 文件大小 | ≤ 10MB |
| 最大行数 | 1000 |

4. **第 3 步：字段映射**

| Excel 列 | 系统字段 |
|---------|---------|
| name | 数字员工名称 |
| code | 内部编码 |
| ... | ... |

5. **第 4 步：预览与校验**

| 检查项 | 失败处理 |
|-------|---------|
| 必填项缺失 | 行标红，提示缺失字段 |
| 编码重复 | 提示「与已有员工重复」 |
| 类型不识别 | 提示「未知类型」 |

6. 用户点击「开始导入」 → 异步执行 → 显示进度
7. 导入完成 → 生成报告（成功 N 条 / 失败 N 条）

## 9. 「配置能力」按钮（FR-DW-3.2.4）

**触发位置**：数字员工详情 → 「能力」 → 「添加能力」。

**操作流程**：

1. 用户点击「添加能力」 → 弹出"选择能力"对话框
2. 列出可添加能力类型：

| 能力类型 | 来源 |
|---------|------|
| 对话 | 内置 |
| RAG 检索 | TECH-RAG |
| Action 调用 | TECH-ACTION |
| MCP 工具 | TECH-MCP |
| Ontology 查询 | TECH-ONT |
| 知识库绑定 | APP-KB |
| 工作流触发 | TECH-WFE |

3. 用户勾选能力，填写：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 能力优先级 | Integer | 是 | 1-10，默认 5 |
| 调用限制 | JSON | 否 | {maxPerHour: 100} |

4. 用户点击「确认」 → 写入 `agent_capability` 表
