## 1. 「创建知识库」按钮（FR-KB-001-02）

**触发位置**：知识库列表页 `/knowledge-base` 右上角「创建知识库」主按钮。

**操作流程**：

1. 用户点击「创建知识库」 → 系统弹出"创建知识库"模态对话框
2. 用户在对话框中填写以下表单：

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|------|------|------|---------|------|
| 名称 | String(2-50) | 是 | 不与现有 KB 重名；不可全空格 | 知识库展示名 |
| 编码 | String[a-z0-9-]{3,30} | 是 | 唯一；只允许小写字母数字连字符 | 内部标识，用于 API |
| 描述 | Text(0-500) | 否 | - | 业务说明 |
| 图标 | Image(URL) | 否 | - | 默认图标 |
| 标签 | Array[String] | 否 | 每个 ≤ 10 字符，最多 5 个 | 用于检索筛选 |
| 可见范围 | Enum | 是 | PRIVATE/ORG/PUBLIC | PRIVATE 仅创建者，ORG 限组织，PUBLIC 全平台 |
| 所属组织 | OrgRef | 条件 | 可见范围=ORG/PUBLIC 时必填 | 组织树选择 |
| 嵌入模型 | Enum | 是 | 默认 `text-embedding-v3` | Qwen/BGE/m3e/Ada |
| 切片策略 | Enum | 是 | FIXED/PARAGRAPH/SECTION/CUSTOM | 默认 FIXED |
| 切片配置 | JSON | 条件 | 切片策略=FIXED 时必填 | {chunkSize: 500, overlap: 50} |
| 自定义规则 | JSON | 条件 | 切片策略=CUSTOM 时必填 | 自定义切片 SPI |

3. 实时校验：必填项缺失时按钮置灰，校验失败时字段下方红色提示
4. 用户点击「确认创建」 → 系统生成知识库记录 → 自动跳转到详情页 → Toast 提示「创建成功」
5. 失败处理：名称/编码重名时 Toast 提示「名称已被占用」

**结果反馈**：知识库状态自动变为 `BUILDING`（空文档），可立即上传文档。

## 2. 「上传文档」按钮（FR-KB-002-01）

**触发位置**：知识库详情页 → 「文档管理」标签页 → 「上传文档」按钮。

**操作流程**：

1. 用户点击「上传文档」 → 弹出上传对话框
2. 用户选择文件（支持 PDF/Word/Markdown/Excel/PPT/HTML/TXT，单文件 ≤ 500MB）
3. 用户选择上传方式：

| 方式 | 说明 |
|------|------|
| 单文件上传 | 一次选择一个文件 |
| 批量上传 | 一次选择多个文件（最多 50 个/批） |
| 文件夹拖拽 | 拖入文件夹自动递归上传 |
| URL 抓取 | 输入 URL，自动抓取并解析为文档 |

4. 用户填写以下元数据（可选）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 标签 | Array[String] | 否 | 用于检索 |
| 自定义切片策略 | Enum | 否 | 覆盖 KB 默认 |
| 跳过审核 | Boolean | 否 | 上传后自动 APPROVED（默认 false） |

5. 用户点击「开始上传」 → 文件进入解析队列 → 上传进度条实时显示（解析/切片/向量化）
6. 上传完成 → 文档状态变为 `PARSED` → 切片数实时统计
7. 失败处理：单文件失败不影响其他文件，错误明细可下载 CSV

**结果反馈**：文档列表新增一行，状态显示「解析中/已解析/失败」。

## 3. 「创建切片策略模板」按钮（FR-KB-003-01）

**触发位置**：知识库详情页 → 「检索配置」标签页 → 「切片策略」区 → 「保存为模板」。

**操作流程**：

1. 用户配置完切片参数后，点击「保存为模板」
2. 弹出"新建切片策略模板"对话框：

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|---------|
| 模板名称 | String(2-30) | 是 | 唯一 |
| 适用文档类型 | Array[Enum] | 否 | PDF/DOCX/MD/XLSX/PPT/HTML/TXT |
| 切片参数 | JSON | 是 | {chunkSize, overlap, splitterType, ...} |

3. 用户点击「确认保存」 → 模板保存到 `kb_chunk_template` 表
4. 后续可被其他 KB 引用

## 4. 「绑定业务 RAG Agent」按钮（FR-KB-007-01）

**触发位置**：知识库详情页 → 「消费方」标签页 → 「绑定 Agent」。

**操作流程**：

1. 用户点击「绑定 Agent」 → 弹出"选择 Agent"对话框
2. 列表展示所有 `agentType=BUSINESS_RAG_KB` 的数字员工
3. 用户勾选 1~N 个 Agent（多选），可填写：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 主知识库标记 | Boolean | 否 | 多 KB 时标记默认 KB |

4. 用户点击「确认绑定」 → 写入 `dw_kb_binding` 表
5. 触发数字员工 Agent Card 自动刷新（通过 TECH-MSG 通知）
6. COPILOT 通过 Nacos A2A Registry 重新发现该 Agent

**结果反馈**：消费方列表新增 Agent 行，可点击查看绑定详情。

## 5. 「创建版本快照」按钮（FR-KB-005-01）

**触发位置**：知识库详情页 → 「版本」标签页 → 「创建版本」。

**操作流程**：

1. 用户点击「创建版本」 → 弹出"创建版本快照"对话框：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 版本号 | String | 是 | 自动建议 semver（如 v1.2.0） |
| 版本描述 | Text(0-200) | 否 | 变更说明 |
| 快照类型 | Enum | 是 | DOCUMENT/CHUNK/INDEX |
| 标签 | Array[String] | 否 | 如 "stable"、"beta" |

2. 用户点击「确认创建」 → 系统异步生成快照（索引快照走 Milvus collection snapshot）
3. 创建完成 → 版本列表新增一行 → Toast 提示

**结果反馈**：版本变为「稳定可用」状态，可一键回滚到此版本。

## 6. 「切片审核」按钮（FR-KB-002-04）

**触发位置**：知识库详情页 → 「文档管理」标签页 → 单文档「预览」 → 切片列表「审核」操作。

**操作流程**：

1. 审核员打开文档预览，看到双栏视图（左侧原文 / 右侧切片）
2. 切片列表每一行有「通过」「驳回」「编辑」按钮：

| 按钮 | 行为 |
|------|------|
| 通过 | 切片状态 → `APPROVED`，写入审核人/时间 |
| 驳回 | 弹出原因输入框（必填 5-200 字）→ 切片状态 → `REJECTED` |
| 编辑 | 进入切片编辑模式（修改 content / 调整边界 / 合并/拆分） |

3. 审核进度在文档详情页头部显示（如「已审核 35/120」）
4. 全部审核完成后 → 文档状态自动变为 `APPROVED` → 触发索引重建

## 7. 「权限分配」按钮（FR-KB-004）

**触发位置**：知识库详情页 → 「权限」标签页 → 「添加成员」。

**操作流程**：

1. 用户点击「添加成员」 → 弹出"权限分配"对话框
2. 用户选择主体类型：

| 类型 | 说明 |
|------|------|
| 用户 | 输入用户名/邮箱搜索 |
| 角色 | 从 TECH-IAM 角色列表选择 |
| 组织 | 从组织树选择 |

3. 用户选择权限角色：

| 角色 | 权限范围 |
|------|---------|
| KB_ADMIN | 全部权限（CRUD、权限分配、删除） |
| KB_EDITOR | 上传/编辑文档、审核切片 |
| KB_VIEWER | 仅查看文档列表与预览 |
| KB_CONSUMER | 仅检索（数字员工/Copilot 调用） |

4. 用户点击「确认分配」 → 权限写入 `kb_permissions` 表
5. 受影响用户刷新页面后看到该 KB 出现在权限列表中

## 8. 「回滚版本」按钮（FR-KB-005-02）

**触发位置**：知识库详情页 → 「版本」标签页 → 版本行「回滚到此版本」。

**操作流程**：

1. 用户点击「回滚到此版本」 → 弹出二次确认对话框（高危操作）
2. 用户输入知识库名称以确认（防误操作）
3. 用户选择回滚范围：

| 范围 | 说明 |
|------|------|
| 仅文档 | 恢复文档快照（不影响切片与索引） |
| 仅切片 | 恢复切片状态（重新切片） |
| 仅索引 | 恢复 Milvus collection 快照 |
| 全部 | 完整回滚（耗时较长） |

4. 用户点击「确认回滚」 → 异步执行回滚 → 进度条显示
5. 回滚完成 → Toast 提示「已回滚到版本 v1.x」 → 自动通知绑定 Agent 刷新缓存（通过 A2A）

## 9. 「检索测试」按钮（FR-KB-003-02）

**触发位置**：知识库详情页 → 「检索配置」标签页 → 「测试检索」。

**操作流程**：

1. 用户点击「测试检索」 → 弹出测试面板
2. 用户输入测试 query（最多 500 字）
3. 用户选择检索策略覆盖（可选）：topK、阈值、重排序开关
4. 用户点击「执行测试」 → 系统检索 → 返回 Top-K 段落 + 引用 + 分数
5. 用户可对每个段落点击「👍 / 👎」反馈，反馈用于优化
