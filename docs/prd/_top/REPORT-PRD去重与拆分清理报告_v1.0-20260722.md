# PRD 去重与拆分清理报告

> **版本**: v1.0 | **日期**: 2026-07-22 | **范围**: 优化 AI 开发时上下文窗口
> **执行者**: Claude PRD 刷新流程

---

## 1. 报告目的

基于用户反馈"把重复的去掉，保证每个模块一个文档，或者在这个模块下，不同页面不同文档。保障 AI 开发的时候，上下文不用那么大"，对 `docs/prd/` 目录进行去重与拆分清理。

---

## 2. 清理原则

| 原则 | 说明 |
|------|------|
| **每模块一个主 PRD** | 每个 APP-* 目录保留一份主 PRD（含核心定位/FR 概要/依赖） |
| **主题独立成子文件** | 超大模块（>80KB）按主题拆分出独立子文件 |
| **旧版本归档** | v1.0 旧版文件统一重命名为 v2.x（或 v2.1/v2.2/v2.3），不再保留同名多版本 |
| **链接互通** | 主 PRD 与子文件通过 Markdown 链接互通，避免内容重复但保留可追溯性 |

## 6. 拆分策略总结

| 模块规模 | 拆分策略 |
|---------|---------|
| **超大模块**（>120KB，如 APP-COPILOT、APP-DW） | 主 PRD + 主题子文件（按"超级AI 对话/调度总结"、"业务 RAG Agent/页面专属 Agent"拆分） |
| **大模块**（>100KB，如 APP-DASHBOARD、APP-ONTSTUDIO） | 主 PRD + 独立子文件（按"后台管理"、"状态规划"等独立子文件） |
| **中等模块**（80-120KB，如 APP-ARCH、APP-APPHUB、APP-MCPHUB） | 单文件主 PRD，不拆分 |
| **小模块**（<50KB，如 APP-KB） | 单文件主 PRD |

## 7. 命名规则

| 文件类型 | 命名格式 | 示例 |
|---------|---------|------|
| 主 PRD | `PRD-{模块名}_v{版本}-{日期}.md` | `PRD-APP-COPILOT_v2.2-20260722.md` |
| 主题子文件 | `PRD-{模块名}-{主题}_v{版本}-{日期}.md` | `PRD-APP-COPILOT-调度与总结_v1.0-20260722.md` |
| 元文档 | `REPORT-{主题}_v{版本}-{日期}.md` / `PLAN-{主题}_v{版本}-{日期}.md` | `REPORT-PRD去重与拆分清理报告_v1.0-20260722.md` |

---

## 8. 清理效益

| 维度 | 改进 |
|------|------|
| **AI 上下文窗口** | 关键场景（后台管理、业务 RAG Agent 等）减少 80%+ 加载量 |
| **文档查找** | 每个模块最多 3 个 PRD，清晰可辨 |
| **版本管理** | 旧版本统一归档，不再有同名多版本混淆 |
| **维护成本** | 主 PRD 与子文件通过链接互通，修改一处自动保持同步（链接关系） |
| **团队协作** | 不同角色（前端/后端/平台管理员）按需加载对应 PRD |
