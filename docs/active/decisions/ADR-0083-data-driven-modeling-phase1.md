# ADR-0083：数据逆向建模接入原生本体生命周期

- 日期：2026-10-10
- 状态：本轮实施决策，待业务验收；不代表生产上线批准
- 依据：ADR-0080、ADR-0082、[实施计划](../../superpowers/plans/2026-10-10-data-driven-ontology-integration.md)

## 背景

旧工作台能从 Excel 生成对象、属性和关联，但其 Neo4j 来源存储与发布身份独立于平台。整体合并会形成两个正式模型单源。第一期迁入有界解析、候选编译、语义推荐和审核能力，接入 Builder V2 和原生本体。

## 决策

用户确认边界：逆向建模是可选辅助工作区，正向本体设计仍是完整独立主链路。不得更改正向默认入口、强制用户先上传数据，或使正向模型操作依赖逆向任务/store。两条路径仅在用户明确发布时汇入同一正式本体。

1. `/ontology/model/from-data` 使用平台 PageHeader、Semi UI、业务模型导航。仅开放数据、候选编辑、验证、发布、同步；接口、公理、动作和函数不在首期承诺内。
2. ONT 的 `/api/v1/ont/v2/modeling` 管理租户隔离的来源快照、候选修订和任务。来源行是输入证据；候选和 AI 报告不是生效模型。原始工作簿及其有界 JSON 快照持久化到 PostgreSQL，不另建对象存储依赖。
3. Copilot 从受控供应商配置取得模型。先根据业务问题和已有模型形成全局概念，再分批生成映射。模型输出通过严格契约校验，所有人工确认默认关闭。语义审核与确定性数据校验分开。
4. 修改候选、业务上下文或复用决策会使关联报告失效。保存、生成、发布携带 revision；发布还核对配置摘要，拒绝过期报告。后台任务持久记录状态，服务重启后未完成任务标为中断。
5. 新建、复用、扩展须由用户确认；正式类型身份不依赖文件内容、样本数或批次。类型通过既有 WIP、checksum、预检和 apply 流程发布，关系在类型之后发布。逐项记录结果并允许续传，不承诺多资源原子提交。已有平台的破坏性变更门禁不能被绕过。
6. 数据通过受控 PostgreSQL staging 表和原生 `pg_table` backing datasource 同步，正式实例/关系仍由原生仓库管理。租户作用域传入 staging 读取，保留来源追溯；重复同步保持身份稳定，首期不自动删除缺失业务记录。
7. 输入容量、压缩包展开量、单元格和关系展开量有上限。画像和实例预览明确样本边界，不能将样本统计称为长期业务规则。

## 正向与逆向共存保护

- 类型发布加原生 RID 级协调锁；已有不同 WIP 必须先由原编辑者处理。原生 save 增加可选 `preserve_existing`，apply 增加可选 `expected_payload_checksum`，防止在检查之后覆盖另一份草稿或发布未经审阅的载荷。默认正向调用行为保持兼容；原生模块不依赖逆向模块。
- 生成任务持有数据库会话锁，新工作进程只能回收无活跃锁的中断任务，不能将其他 worker 的任务视为服务重启。
- 单属性身份与原生 backing datasource 的字符串主键一致。复用既有对象时按业务身份核对并沿用已有主键；复合身份新建采用有序 JSON tuple，复用时保留既有存储主键。首期不声称提供原生复合主键迁移能力。

## 验收边界

2026-10-10 用户追加：首期候选必须支持有业务证据的子类与多级层次，而非只生成一级类。采用 `parentClassId` 和 `inheritanceReason` 记录单继承分类及依据，明确区分 is-a 与 part-of。空依据、失效引用、自继承、继承环、超过平台限深，以及父子身份或属性类型不兼容均须阻断。原生仓库已提供 `parent_class`、subclass 公理闭包和层级查询；首期复用这些能力，不引入独立推理链路。

子类显式包含父类共有属性、沿用其属性 RID 及身份定义。实例只映射到最具体类别，父类允许仅作概念；祖先和子孙同身份重复映射须先人工消歧。父类对象查询应通过平台闭包包含子孙实例，不通过每层复制实例实现。继承证据仍须业务人员审核，程序校验不等于证明业务语义正确。

固定制造齐套和客户订单两套样本，覆盖跨表同类、一表多类和复合身份；缺少交期/供应商数据的问题必须报告不可回答。固定样本与问题是工程验收基线，仍需业务人员确认语义，不能把自动测试通过写成业务批准。

实际执行新的纯逻辑/API/PG 测试、现有六组非特权 PostgreSQL 回归、前端类型和构建，以及独立环境浏览器导入到查询闭环。真实模型调用与受控响应测试分别记录；缺运行证据的能力保留待验收状态。

## 2026-10-10 用户确认：本体为核心的逆向闭环

逆向主流程以审核、校验、接入原生本体并核对发布结果为完成；实例同步移为发布后的可选操作。新增本体结构校验与独立完整数据校验，结构报告 `scope=ontology`，嵌套 `dataValidation.canSync`。空编号、转换失败、重复实体冲突等数据问题仅阻断数据同步；类/属性/继承/关系结构错误、未审核定义、原生接入冲突仍阻断本体发布。主键定义正确不代表当前文件主键值完整或长期业务唯一性已经证明。

同步前重新执行现有完整编译校验；本轮不新增部分记录自动导入、静默跳过、自动填主键或问题记录队列。问题按位置与原因汇总，保留总次数及有界样本，用户修正候选/数据后重新审核、校验并按既有指纹与迁移规则继续。无业务身份继续明确使用来源记录技术身份，不声称跨文件对齐；继承仍要求父子一致且非空身份，不能为了发布绕过原生要求。

原生发布接口、正向默认流程、版本/WIP/破坏性变更保护保持原有单源；对现有数据错误导致阻断的候选重新校验会生成新作用域报告，旧报告不直接视为结构发布许可。详细实施见[本体发布闭环计划](../../superpowers/plans/2026-10-10-reverse-ontology-publication-loop.md)。

## 2026-10-10 用户确认：逆向模型业务审核完善

增加关系基数与依据审核、实体/集合关联区分和复合键完整性校验。替代唯一键须明确声明、提供依据并人工确认；接入时验证唯一性。身份规则与数据完整性分离，保留未确定、候选、已确认及来源记录策略。结构化证据区分源字段、业务说明与推断，不把样本统计当长期规则。旧候选兼容并提示缺少审核信息，不自动修改已发布类型。

提供只读原生类型对比及发布后验收，检查定义、属性、身份、继承和关系是否与方案一致，识别后续漂移。新能力限定于独立 modeling 工作区，不修改正向内核与原生契约，不自动合并同名概念或重发真实本体。详细见[审核完善计划](../../superpowers/plans/2026-10-10-reverse-model-assurance.md)。
## 2026-10-10 审核易用性补充（用户已批准）

逆向候选的 included 默认为 true，表示本次发布范围，与审核 accepted 独立。暂缓项仍完整保存在草稿；服务端结构校验、证据、原生冲突、方案与可选同步使用同一范围。选择范围不得留下悬空父类或关系端点，不允许全部暂缓后发布空模型。完整原始草稿仍参与配置指纹。已有部分发布结果后禁止改变范围，避免丢失重试资源记录。统一确认按钮只确认用户审阅的有效规则，不补写业务依据、不推断基数。

这是一项逆向候选编排能力，并非新增正式本体状态或原生发布包。ADR-0080 的原生“先声明后注册”口径保持不变；逆向候选自身的父类与端点依赖仍按既有更严格检查执行。暂缓不能删除/退役已发布对象；已产生发布结果后范围锁定，后续增量应另建候选并显式复用原生定义，不隐式追加本次发布。发布成功仅表示本次所选定义接入完成，不能声称暂缓候选或全部业务问题已完成。AI 不能替用户暂缓任何候选。没有核验 Palantir 官方规范或内部标准，本决策不声明相关认证。

## 2026-10-11 Excel 逆向生成质量与稳定性

用户要求逆向与正向本体对齐、同输入生成稳定。本轮采用租户隔离的持久化生成基线，全量数据预检及最多两轮受限修正。输入指纹覆盖来源行/表头、业务说明/问题、原生定义、候选 schema 与策略版本；命中沿用首次完整候选，不复用人工审核和修改。已发布来源禁止重新生成覆盖。修正仅作用于未审核的新候选，以本地预检允许的字段补充身份或修复关系条件，不自动修改数据、发布范围、基数或唯一键确认；结构或数据回退不接受。原生正向仍是发布/版本单源，逆向未覆盖能力须明确告知，不声称全平台功能已自动生成。详见[实施计划](../../superpowers/plans/2026-10-11-excel-modeling-quality.md)。
# 2026-10-11 数据处理补充

用户已授权 AI 提案、人工确认与问题隔离的完整同步链路。数据处理复用实例非身份属性修订；已发布本体定义与业务身份不绕过原生迁移。严格同步保留，新增按当前检查哈希明确确认的合格子集同步。原始来源及暂缓记录保留，依赖缺失端点的关系不写入；部分同步不删除历史数据。实现边界见[数据处理计划](../../superpowers/plans/2026-10-11-modeling-data-treatment.md)。
