## 2. 范围与不做的事

### 2.1 IN SCOPE（本批次交付）

每个域必须达到：
1. **路径前缀对齐 spec**：`/api/v1/<domain>/...`。
2. **5 步模式完整**（per `per-app-integration-checklist.md`）：
   - `install_auth(app)` 在 `create_app()` 第一行
   - 每个 handler 第一行 `require_tenant(ctx)`
   - 写 handler 用 `outbox.append(Event.create(...))` 同事务
   - 出向调用用 `BearerAuth` + `OutgoingAuthMiddleware`
   - `tests/test_<app>_tenant.py` ≥ 3 cross-tenant negative
3. **OpenAPI security 三段式**：bearerAuth + tenantHeader + oidcScopes 已就位（v3.0 已批量升级）。
4. **业务实现策略**：只读 endpoint 优先 in-memory + 关键 endpoint 接真实存储（见 §5）。
5. **`pytest` 全绿**：`pytest packages/<app>/tests/` + `pytest infra/tests`。

### 2.2 OUT OF SCOPE（明确不做）

- **业务持久化层**：dashboard / apphub / arch 的数据来源先用 in-memory dict / 静态 JSON fixtures；真实 Paimon / Iceberg / Postgres 接入属于 v3.2 sub-batch。
- **copilot LLM provider 路由**：33 个 endpoint 里只有 `auth/login`、`actions/execute`、`analysis/audit-sql` 等少数会触发真实 LLM 调用；其他 `getConversations` / `getPlans` 等历史 / 配置读取走 in-memory。完整 LLM 路由属于 W5-5 (llmgw) 子任务。
- **Copilot A2A 协议层完整实现**：`/api/v1/copilot/a2a/*` 2 个 endpoint 在本批次只做 spec-aligned stub（返回 501 Not Implemented + 错误体）；真实实现依赖 mate-app-a2a 包（P2 W3）。
- **Flowable BPMN 集成**：`arch` 不涉及 BPMN（属于 W3-4 / mate-app-wfe / P2 W3）。
- **dashboard 持久化**：notifications / todos / metrics / anomalies / workers / deliverables / api-keys 全部仍 in-memory；真实 DB 接入属于后续 sub-batch。
- **前端 SPA 页面**：`metaplatform-frontend` W6 batch 接力，与本 SPEC 不耦合。

### 3.2 5 步模式在本批次的强制点

**步骤 1 install_auth**：
- 新包 main.py 必须 `from mate_platform.auth import install_auth`，`install_auth(app)` 作为第一行。
- 现有 `dashboard.py` 的 router 已在 `mate-tech-iam` 的 main.py 链上（`app.include_router(dashboard_router)`）；需确认 `install_auth` 已被该包 main.py 调用一次（已就位，复检即可）。

**步骤 2 require_tenant**：
- 每个 handler 第一行 `ctx = request.state.ctx; require_tenant(ctx)`。
- dashboard 现状：handler 内有 `_require_ctx()` helper 但需逐函数审计（14 个 GET + 9 个 PUT/POST/DELETE 共 34 个）—— 全部加 `require_tenant` 调用。
- 新包所有 handler 一开始就遵守。

**步骤 3 outbox**：
- 仅写 handler 需要（POST / PUT / DELETE / PATCH）。
- dashboard 写 handler：`auth/login`、`settings PUT`、`notifications/{id}/read PUT`、`notifications/read-all POST`、`todos/{id}/action POST`、`deliverables/{id}/download POST`、`anomalies/{id}/analyze POST`、`anomalies/{id}/remediate POST`、`api-keys POST`、`anomaly-rules POST/PUT/DELETE`、`sessions/{id} DELETE`、`api-keys/{id} DELETE`、`deliverables/{id} DELETE`。
- 新包本批只实现 GET（apphub 5 GET + arch 27 GET），无 outbox 写需求。
- copilot 包含 `auth/login` POST、`actions/execute` POST、`analysis/*` POST、`generate/*` POST、`chat/multimodal/upload` POST、`queries/execute` POST、`scheduling/execution/start` POST、`scheduling/intent/detect` POST、`scheduling/plan/generate` POST、`a2a/delegate` POST 等 11 个 POST——逐个加 outbox event。

**步骤 4 BearerAuth + OutgoingAuthMiddleware**：
- 新包若调外部服务（apphub → arch / kb；arch → ontology / kb / rag / agent；copilot → llmgw / agent），用 `mate_clients.security.BearerAuth` + `OutgoingAuthMiddleware`。
- in-memory endpoint（直接返回 fixtures）不需 step 4。

**步骤 5 ≥3 cross-tenant negative**：
- 每包 `tests/test_<app>_tenant.py` 必须含 wrong-tenant / missing-scope / no-tenant 三 case。
- dashboard 现状：0 个 tenant test（必须新增）。

### 3.3 业务流程

以 copilot `/chat/multimodal/upload` 为例：

```
1. POST /api/v1/copilot/chat/multimodal/upload
2. install_auth 中间件 → 注入 ctx
3. handler: ctx = request.state.ctx; require_tenant(ctx)
4. 校验 multipart/form-data；计算 sha256；写 outbox event (copilot.multimodal.uploaded)
5. 用 OutgoingAuthMiddleware 调 mate-tech-llmgw /api/v1/llmgw/embeddings 拿向量（in-memory stub 返 1536 维 fixture）
6. 调 mate-clients.minio.buckets 上传原文件
7. 写 outbox event (copilot.multimodal.indexed)
8. commit session；返回 201 + {asset_id, sha256, url}
```

in-memory 阶段：minio 上传改为 `repositories/in_memory.put(asset_id, bytes)`；embedding stub 返固定 numpy array。

## 5. 数据来源策略

### 5.1 in-memory fixtures

每包 `repositories/in_memory.py` 用 `dataclass` + `dict` 持久化：

```python
@dataclass(slots=True)
class ApphubApp:
    id: str
    name: str
    group_id: str
    description: str
    homepage: str

_APPS: dict[str, ApphubApp] = {
    "kb": ApphubApp(id="kb", name="Knowledge Base", group_id="tech", ...),
    "rag": ApphubApp(id="rag", name="RAG Service", group_id="tech", ...),
    # ... ~15 fixtures
}

def list_apps() -> list[ApphubApp]:
    return list(_APPS.values())
```

**关键约束**：
- 多 tenant 通过 `tenant_id` 隔离：每 tenant 独立 dict `{tenant_id: {...}}`。
- 5 步 step 5 测试用 2 个 tenant 验证 isolation。
