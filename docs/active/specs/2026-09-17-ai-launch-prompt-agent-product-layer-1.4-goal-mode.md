## GOAL

收敛 1.x 的安全欠账——三件都是"**建了但没兜住**"：包络四维**只有 tools 真拦人**；沙箱**按厂商而非代码来源分层**；**审批没角色、动作没审计**。

## 锁死决策

- 包络四维 `(tools, action_rids, kb_ids, markings)` —— **每维都要在执行侧真的拦人**（不能只"判了不拦"）
- **沙箱分层键从「谁出品的」改为「代码来源」**：模型生成 / 子员工执行的代码**即使来自内置员工也不可信**（ADR-0040 现状是安全缺陷）
- **先修订 ADR-0040 再实现**（分层键错了，照旧前提做等于白做）
- 审批角色与审计**复刻既有平台做法**，不另造
- 1.3 已定语义**别改**：越权 → 转 proposal；深度超限 / 跨租户 → 硬拒
- **LangChain 类型不得进公开契约**（R10）；**不用 `interrupt()`**；**不用裸 dict 作状态 schema**

## 任务 1 · 包络四维真收敛

**现状**（1.3 自标）：四维在「员工定义 + 派活判定」两侧贯通，但**执行侧只有 `tools` 真的拦人**。

| 维度 | 要做什么 |
|---|---|
| `tools` | 已拦，保持 |
| **`action_rids`** | 员工调 Action 时，**未在包络内的必须拒** |
| **`kb_ids`** | 知识检索**限定在包络内的知识库** |
| **`markings`** | 带标记数据不得超过包络的 marking 集合——**复用既有 marking 合取门**，别另造 |

**判据**：四维**各有负例**（越维被拒）；只收窄放行；既有链路不回归。

## 任务 2 · 沙箱按代码来源分层

1. **先修订 `docs/active/decisions/ADR-0040-sandbox-architecture.md`**：§2.1 分层键由「厂商身份」改为「**代码来源**」，写明理由
2. 再实现：模型生成 / 子员工执行的代码 → **最强隔离**；人工编写且输入已校验 → 中等

**判据**：生成代码走强隔离（**有断言，不是纸面**）；ADR-0040 已修订且与实现一致；隔离断言用**非超级用户角色**。

## 任务 3 · 审批角色与审计

1. **审批角色**：**谁有权 `approve`**——不是任意登录用户都能确认
2. **审计**：每次派活 / 审批 / 越权转 proposal 落**审计行**（硬规则 #9）

**判据**：无审批角色者 approve **被拒**；越权转 proposal 有审计行；审批有审计行。
