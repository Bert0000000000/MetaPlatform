# Mate Platform 运维手册（v1.0）

> 版本: v1.0 · 日期: 2026-09-09 · 配套: `v1.0-user-manual.md` / `v1.0-known-limitations.md`

## 1. 拓扑

- **入口**：Vite/静态前端 (9250) → API Gateway (8100) → 17 域服务容器。
- **身份**：Keycloak (8080 realm=metaplatform) + mate-auth-service (8101)。
- **数据**：PostgreSQL（metaplatform / metaplatform_ont / iceberg_catalog）、
  Redis、Kafka、MinIO (9000, buckets mate-warehouse 等)、Milvus、Neo4j。
- **编排**：Temporal (7233) + mate-temporal-worker（自愈探针周期 30s）。
- **数据面（可选）**：Trino (8088，JDBC Iceberg metastore)、Flink+Paimon
  （docker-compose.paimon.yml，互斥窗口运行）。

## 2. 日常操作

```bash
# 健康检查
curl -s http://localhost:8100/healthz
curl -s http://localhost:9250/ -o /dev/null -w '%{http_code}\n'

# 全栈重启（env 变更后）
docker compose -f docker-compose.yml -f docker-compose.task5.yml up -d

# 恢复服务（依赖 PG 就绪后再启动依赖方）
docker start mate-tech-ont mate-tech-orchestrator mate-temporal-worker
```

## 3. 关键安全配置

- `LEGACY_LOGIN_COMPAT=false`、`INSECURE_SKIP_SIGNATURE=false`（生产基线）：
  服务强制 Keycloak JWKS RS256 验签；`SERVICE_CLIENT_SECRET` 必须由
  SealedSecret/ExternalSecret 注入（.env 仅限本机开发）。
- 租户三道防线：API rid 前缀校验（403/404）→ repo tenant 过滤 → PG RLS。
- 禁止 fallback：生产 profile 下 local LLM provider 与 legacy 登录均拒绝启动。

## 4. 数据面（Trino / Paimon）

```bash
# Trino 单启（~1 分钟 healthy）；配置 infra/trino/etc（JDBC Iceberg metastore）
docker compose -f docker-compose.trino.yml up -d
python scripts/trino_query.py "SELECT count(*) FROM postgresql.public.ont_object_type"

# Paimon（与 Trino 互斥窗口；Flink standalone）
docker compose -f docker-compose.paimon.yml up -d
MSYS_NO_PATHCONV=1 docker exec mate-flink-jm ./bin/sql-client.sh -f /sql/paimon_sprint5.sql
```

## 5. 故障处理

| 症状                                       | 处置                                                                                                                                               |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 容器反复 Restarting                        | `docker logs --tail 50 <c>`；常见为依赖（PG/Keycloak）未就绪的暂态——先恢复依赖再 `docker start <c>`                                                |
| PG "database system is starting up" 长时间 | 停止依赖服务（keycloak/ont/orchestrator/temporal-worker）静默恢复；就绪后按序拉起。PG WAL 崩溃恢复自愈（无数据损失）                               |
| Docker Desktop 端口转发间歇 000            | 宿主↔VM 转发层抖动；容器内网络验证（docker exec），必要时重启 Docker Desktop                                                                      |
| Trino 启动循环                             | 检查 `infra/trino/etc/catalog/iceberg.properties`（catalog type 合法值与 PG/S3 连通性）；修复后 `docker compose -f docker-compose.trino.yml up -d` |
| 资源预算                                   | **Trino + Milvus + kind 集群不可同驻**（VM 内存）；分窗口运行                                                                                      |

## 6. 备份与恢复

- PostgreSQL：`docker exec mate-postgres pg_dump -U meta metaplatform > backup.sql`；
  恢复 `psql < backup.sql`。PG 崩溃后自动 WAL 恢复（历史两次实测自愈）。
- MinIO：mate-warehouse bucket（Iceberg/Paimon 数据与多模态对象）——
  对象存储目录持久化在 `/data` 卷。
