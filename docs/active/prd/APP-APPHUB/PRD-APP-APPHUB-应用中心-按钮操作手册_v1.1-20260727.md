## 0. 「创建应用」按钮（FR-APPHUB-4.1.2）

**触发位置**：`/apps` 应用列表页 → 右上角「创建应用」主按钮。

**操作流程**：

1. 用户点击「创建应用」 → 系统弹出"创建应用"模态对话框
2. 用户在对话框中填写以下表单：

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|------|------|------|---------|------|
| 应用名称 | String(2-50) | 是 | 唯一；不可全空格 | 应用展示名 |
| 应用编码 | String[a-z0-9-]{3,30} | 是 | 唯一；只允许小写字母数字连字符 | 内部标识，用于 API |
| 应用类型 | Enum | 是 | 业务应用 / 系统应用 / 模板应用 | 用于分组 |
| 应用描述 | Text(10-500) | 是 | 至少 10 字 | 业务说明 |
| 应用图标 | Image(URL) | 否 | ≤ 2MB | 默认图标 |
| 所属分类 | Ref | 是 | 从分类树选择 | 业务/财务/HR/IT/通用 |
| 可见范围 | Enum | 是 | PRIVATE / ORG / PUBLIC | PRIVATE 仅创建者，ORG 限组织，PUBLIC 全平台 |
| 所属组织 | OrgRef | 条件 | 可见范围=ORG/PUBLIC 时必填 | 组织树选择 |
| 标签 | Array[String] | 否 | 每个 ≤ 10 字符，最多 5 个 | 用于检索筛选 |
| 负责人 | Ref | 是 | - | 默认为当前用户 |

3. 实时校验：
   - 必填项缺失时按钮置灰
   - 校验失败时字段下方红色提示
4. 用户点击「确认创建」 → 系统生成应用记录 → 自动跳转到应用详情页 → Toast 提示「创建成功」
5. 失败处理：名称/编码重名时 Toast 提示「名称已被占用」

**创建后默认包含的内容**：

| 内容 | 说明 |
|------|------|
| 应用骨架 | 空白应用，包含默认首页 |
| 默认权限 | 仅创建者可见 |
| 默认菜单 | 「首页」+「设置」 |
| 默认数据模型 | 空 |
| 默认表单 | 空 |
| 默认流程 | 空 |
| 默认数字员工绑定 | 无（需手动添加） |

**创建向导（可选）**：应用类型 = 业务应用 时，会额外展示 3 步向导——①选择应用模板（空白/CRM/OA/工单 等预置模板）②选择关联 Ontology（绑定 APP-ONTSTUDIO 的概念）③选择关联数字员工（APP-DW 提供的专属 Agent）。

**相关联动**：创建成功后，应用自动出现在 APP-DASHBOARD 工作台「我的应用」区；如果绑定了数字员工，Agent 会发布到 Nacos A2A Registry，可被 SuperAI 调度；如果绑定了 Ontology，会触发 APP-ONTSTUDIO 的概念引用计数更新。

**结果反馈**：应用状态 `DRAFT`（草稿） → 用户可继续编辑 → 发布后变为 `PUBLISHED`；应用列表新增一行，状态显示「草稿/已发布」。

## 0.1. 「创建模块」按钮（FR-APPHUB-4.1.3）

**触发位置**：应用详情页 → 「模块」标签页 → 「创建模块」。

**操作流程**：

1. 用户点击「创建模块」 → 弹出"创建模块"对话框
2. 用户填写以下表单：

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|---------|
| 模块名称 | String(2-30) | 是 | 唯一于应用内 |
| 模块编码 | String[a-z0-9-]{3,30} | 是 | 唯一 |
| 模块类型 | Enum | 是 | 表单 / 列表 / 报表 / 看板 / 流程 / 自定义 |
| 关联数据模型 | Ref | 条件 | 类型=表单/列表时必填 |
| 描述 | Text | 否 | - |
| 排序 | Integer | 是 | 默认追加末尾 |
| 可见性 | Enum | 是 | 所有人 / 指定角色 / 指定组织 |

3. 用户点击「确认创建」 → 模块创建完成 → 自动进入模块设计器

## 0.2. 「创建表单」按钮（FR-APPHUB-4.2.1）

**触发位置**：模块详情页 → 「表单」区 → 「创建表单」。

**操作流程**：

1. 用户点击「创建表单」 → 进入表单设计器画布
2. 系统提示选择创建方式：

| 方式 | 说明 |
|------|------|
| 空白创建 | 直接进入空白画布 |
| 从模板创建 | 选择平台预置模板（如「请假申请」「报销申请」） |
| AI 生成 | AI 根据自然语言描述生成表单 |
| 从 Excel 导入 | 上传 Excel 自动识别字段 |

3. 用户选择方式后，进入设计器主界面：
   - 左侧：字段组件库（文本/数字/日期/单选/多选/文件/富文本/级联等 30+ 组件）
   - 中间：画布（拖拽布局，所见即所得）
   - 右侧：字段属性面板（标签/默认值/校验/权限/联动）
4. 用户拖拽字段到画布 → 配置每个字段的属性 → 实时预览
5. 用户点击「保存」 → 写入 `form_definition` 表 → 表单列表新增一行

**创建后默认包含的内容**：

- 表单 ID、版本号 v1
- 默认字段：标题、创建人、创建时间
- 默认权限：所有人可见，管理员可编辑

**结果反馈**：Toast 提示「创建成功」 → 自动跳转到表单字段编辑界面。

## 0.3. 「创建流程」按钮（FR-APPHUB-4.3.1）

**触发位置**：模块详情页 → 「流程」区 → 「创建流程」。

**操作流程**：

1. 用户点击「创建流程」 → 进入流程设计器画布（基于 FlowGram.AI）
2. 系统提示选择创建方式：

| 方式 | 说明 |
|------|------|
| 空白创建 | 直接进入空白画布 |
| 从模板创建 | 选择平台预置流程模板 |
| AI 生成 | AI 根据自然语言描述生成流程节点 |

3. 用户选择方式后，进入设计器主界面：
   - 左侧：节点库（开始/审批/分支/并行/会签/通知/Action/结束等 20+ 节点）
   - 中间：画布（拖拽节点，连线配置流转条件）
   - 右侧：节点属性面板（审批人/条件/超时/通知）
4. 用户拖拽节点到画布 → 连接节点（配置流转条件）→ 配置每个节点的属性
5. 用户点击「保存」 → 写入 `process_definition` 表

**结果反馈**：流程列表新增一行，状态显示「草稿」。

## 0.4. 「从模板创建应用」按钮（FR-APPHUB-4.1.4）

**触发位置**：应用列表页 → 「从模板创建」次按钮。

**操作流程**：

1. 用户点击「从模板创建」 → 弹出"选择模板"对话框（左侧分类 + 右侧模板）
2. 用户选择模板：

| 模板分类 | 示例 |
|---------|------|
| CRM | 客户管理、销售机会、合同审批 |
| OA | 请假申请、报销申请、用车申请 |
| HR | 入职、转正、离职、调岗 |
| IT | 故障申报、需求审批、变更管理 |
| 财务 | 付款审批、预算申请、对账 |

3. 用户点击「使用此模板」 → 弹出"应用基础信息"对话框（参考 §0 创建应用表单）
4. 用户填写应用名称、编码、负责人等 → 点击「确认」
5. 系统从模板复制：
   - 应用结构（菜单、页面）
   - 数据模型（实体、字段）
   - 表单（含字段配置）
   - 流程（含节点和连线）
   - 权限（默认角色配置）
6. 系统提示「模板已应用」 → 跳转应用详情页 → 用户可在基础上修改

**结果反馈**：Toast 提示「应用创建成功，已应用模板 XXX」。

## 1. 「表单全局设置」按钮（FR-APPHUB-4.3.5）

**触发位置**：表单设计器画布空白处右键 → 「表单全局设置」。

**操作流程**：

1. 用户右键画布空白处 → 弹出右键菜单 → 选择「表单全局设置」
2. 弹出"表单全局配置"对话框（左侧导航 + 右侧详情）：

### 1.1 基础设置

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|------|------|------|---------|------|
| 表单名称 | String(2-50) | 是 | 唯一 | - |
| 表单编码 | String[a-z0-9-]{3,30} | 是 | 唯一；小写 | - |
| 表单描述 | Text(0-200) | 否 | - | - |
| 表单分类 | Enum | 是 | 申请类/审批类/登记类/展示类 | 用于检索 |

### 1.2 提交设置

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 提交按钮文案 | String(2-10) | 是 | 默认「提交」 |
| 提交后行为 | Enum | 是 | 跳转页面 / 弹窗提示 / 关闭 |
| 提交后跳转 URL | URL | 条件 | 提交后行为=跳转时必填 |
| 草稿自动保存 | Boolean | 否 | 默认 false |

### 1.3 权限设置

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 表单可见范围 | Enum | 是 | 所有人/指定角色/指定组织 |
| 字段权限 | JSON | 否 | 按角色/字段设置可见/可编辑/必填 |
| 提交频率限制 | Integer(/h) | 否 | 默认不限 |

### 1.4 数据设置

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 数据存储 | Ref | 是 | 关联数据模型 |
| 主键字段 | Ref | 是 | - |
| 提交触发流程 | Ref | 否 | 绑定工作流 |
| 数据脱敏 | JSON | 否 | 字段级脱敏规则 |

### 1.5 通知设置

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 提交通知 | Multi | 否 | 邮件/IM/Webhook |
| 通知接收人 | JSON | 条件 | 通知开启时必填 |
| 通知模板 | Ref | 条件 | - |

3. 用户填写完毕，点击「保存」 → 配置写入 `form_config` 表 → 画布实时刷新
4. 用户点击「取消」 → 弹窗关闭，配置丢弃

## 3. 「发布应用」按钮（FR-APPHUB-4.6.1）

**触发位置**：应用详情页 → 头部「发布」按钮。

**操作流程**：

1. 用户点击「发布」 → 弹出"发布应用"向导（3 步）
2. **第 1 步：选择版本**

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|---------|
| 版本类型 | Enum | 是 | 主版本/次版本/补丁 |
| 版本号 | Auto | 是 | semver 自动生成 |
| 发布说明 | Text(0-500) | 否 | - |

3. **第 2 步：检查项**（自动）

| 检查项 | 失败时处理 |
|-------|----------|
| 表单设计完整性 | 必须有至少 1 个字段 |
| 流程节点配置 | 每个节点必须配置审批人 |
| 权限配置 | 必须有可见范围 |
| 集成配置 | 关联 KB/数据源配置完成 |
| 测试用例 | 至少 1 个通过的用例 |

4. **第 3 步：发布范围**

| 范围 | 说明 |
|------|------|
| 全平台 | 所有用户可见 |
| 指定组织 | 多选组织 |
| 灰度发布 | 先 10% 流量 → 监控 1h → 全量 |

5. 用户点击「确认发布」 → 写入 `app_release` 表 → Nacos Config 推送

## 4. 「回滚版本」按钮（FR-APPHUB-4.7.2）

**触发位置**：应用详情页 → 「版本管理」标签页 → 版本行「回滚到此版本」。

**操作流程**：

1. 用户点击「回滚到此版本」 → 弹出二次确认（高危操作）
2. 用户选择回滚范围：

| 范围 | 说明 |
|------|------|
| 仅应用配置 | 不影响已提交数据 |
| 仅表单结构 | 影响后续表单 |
| 仅流程配置 | 影响流程逻辑 |
| 全部 | 完整回滚（数据不丢失） |

3. 用户点击「确认回滚」 → 异步执行 → 显示进度
4. 回滚完成 → Toast 提示 → 自动通知已绑定用户/Agent
