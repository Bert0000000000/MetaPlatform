# PRD-05：Semantic Router

> 关联批次：MP-SR-01 · 所属 Sprint：0
> 状态：`[~] Draft — 待产品评审` · 2026-08-31
> 事实基线：`docs/active/delivery/evidence/MP-SR-01-ACCEPTANCE.md`

## 1. 目标与边界

让 SuperAI 在处理业务请求前，基于当前租户中用户可调用的数字员工和能力，给出可解释的候选路由；模型只可在这些候选中选择执行目标。路由不是业务写操作，也不能替代权限校验、人工确认或 Action 执行。

本期覆盖候选角色 top-k、能力关键词加权、A2A → kernel role → embedding → keyword 的调度链、`routing_decision` SSE 事件和 SuperAI 展示。模型不可用时只可返回明确的受限路由/失败结果，禁止编造成功答复或跨租户回退。

不包含：跨租户路由、用路由结果绕开 Agent/Action 授权，或将 HashEmbedder 作为生产质量的语义模型。

## 2. 用户与主旅程

| 角色 | 需要完成的事 | 成功结果 |
|---|---|---|
| 业务用户 | 在 SuperAI 输入业务请求 | 看到当前候选、最终选中的执行目标和结果摘要 |
| AI 运营人员 | 维护数字员工能力 | 新能力只在所属租户、已授权用户的候选中出现 |
| 平台治理人员 | 审计一次调度 | 能追溯输入、候选、选择原因、模型/降级路径、trace 与租户 |

主流程：用户发言 → 系统读取其租户的可用角色 → 生成并排序 top-k 候选 → 首个 SSE 事件发出 `routing_decision` → 模型在候选中选择或 dispatcher 明确降级 → 调用已授权目标 → 追加最终选择、结果或失败事件。

## 3. 功能需求

1. 候选至少包含角色标识、显示名、分数、命中原因和能力摘要；候选为空时必须明确表示无可用处理者。
2. 排序综合语义相似度与能力关键词命中；top-k 和最小相关性阈值为服务配置，不由前端硬编码。
3. `routing_decision` 必须先于 reasoning/tool 事件发出；预选事件可不含最终选择，最终事件必须标注 selected 或明确未选择。
4. 每次候选检索和执行前均执行租户、角色和能力授权；候选列表本身不得泄露其他租户角色、能力或分数。
5. 模型不能选择候选外目标。A2A、kernel role、embedding、keyword 是受审计的 dispatcher 链，不是静默成功回退。
6. SuperAI 页面应把路由过程作为可读状态展示；用户可区分“模型选择”“确定性调度”“无候选/依赖失败”。

## 4. 数据、接口与审计契约

路由输入至少包含 tenant、主体、会话/请求关联 ID、用户文本和可用角色快照。输出以 SSE `routing_decision` 发布，包含候选、选择、原因、路径和 trace/correlation ID；持久审计不得保存超出合规期限的原始提示词。

候选和选择均是瞬时决策记录，业务副作用仍由目标 Agent 的 ObjectSet、Function 或 ActionType 契约负责。任何写操作必须另有幂等键、人工确认和 Outbox/Audit 记录。

## 5. 安全与异常要求

- 缺少身份、租户或能力授权时失败关闭；不得回退到默认管理员角色。
- provider、A2A 或角色目录不可用时返回可诊断失败事件；不得伪造路由或业务结果。
- 缓存按租户和角色文本版本隔离；角色能力变更必须使旧缓存失效。
- 审计记录需支持按 tenant、session、trace 和选中角色检索。

## 6. 验收标准

代码级验收：top-k 排序、关键词加权、缓存失效、候选约束、SSE 顺序、跨租户拒绝和 provider/dispatcher 异常分支均有自动化覆盖。

正式 GA 验收：两个独立 OpenAI-compatible provider 完成路由、配额、熔断和故障切换；staging 验证 SSE 断线恢复、跨租户拒绝和端到端业务结果；生产镜像没有 memory/echo/demo 静默回退。满足这些条件前状态保持 `[~]`。

## 7. 当前证据与待确认决策

已具备离线路由、dispatcher、SSE 和 SuperAI 展示的条件验收；尚未具备真实 provider/staging 证据。

产品评审需要确认：默认 top-k 与最小相关性阈值、用户是否可手动改选候选、以及路由审计数据的保留期限。未确认前采用“仅展示、不可人工改选”的安全默认值。
