## 1. 目标与范围

按更新的全平台原型统一现有平台的页面结构、视觉与交互。本体工作室贯通“模型定义 → 数据绑定 → 对象查询 → 动作配置 → 校验与发布”，其余入口保持各自职责和真实业务操作。保留现有后台能力、身份、租户边界与治理语义。

范围覆盖平台壳、七个一级入口、常驻 SuperAI 及其所有现有 active 页面。本轮统一浅色顶栏、顶部功能组、左侧页面导航、页头、卡片/表格与工作区状态；建模、类型编辑、映射、发布四段承担主要交互改造，工作台、应用、员工、知识集成和治理页面按新版对应页面模式优化。旧平台八域的业务能力和链接继续可达，通过七入口重新归组；不扩建其他后台业务。

不移植原型的合成客户数据、本地事实库、角色切换、假发布快照、受限演示函数或假同步结果。不新增独立 ObjectType、Binding、Version、Proposal 或 Action 存储。未获真实 API 支持的原型操作保持未开放。

## 3. 方案选择

推荐采用“现有 React 平台内渐进对齐”：保持路由、组件库、后台、身份与发布机制，以导航壳和四段核心交互逐步替换展示层。该方式能让每段独立验证和回退，也能保留本仓库超过原型的分析、地图、编排与使用量能力。

仅换颜色与布局的方案工作量较小，但仍保留横向导航和散落的资源编辑入口，无法达到已选择的交互对齐目标。另起独立前端再接后端会重复状态和权限处理，迁移成本与回归风险较高，本次不采用。

## 4. 页面与路由

### 4.1 平台与本体工作区

平台一级入口采用用户随后选定的产品文档方案：工作台、业务应用、对象探索、本体工作室、数字员工、连接与知识、治理与管理。SuperAI 保持常驻入口、全局 Copilot 与完整 `/superai/chat` 路由；不计入七个一级菜单。旧应用、知识/集成、数据治理和管理能力依据职责归组，旧 URL 不失效。

一级“本体工作室”默认打开 `/ontology/model/graph`，标题为“模型工作台”。全站根入口继续现有 `/home`；已有 `/ontology` 总览链接保留，增加 `/ontology/overview` 兼容别名。对象探索作为独立消费入口，不再套用本体建设导航。

全平台采用平台入口 → 顶部功能组 → 左侧当前组页面导航 → 单资源详情页签。导航、命令索引和面包屑从同一注册表派生；本体页面与域级导航只保留一套，不叠加旧六组侧栏。没有多个功能组的域仍保留清晰的组标题和页面列表。资源内的类型树/切换列表承担对象选择，与页面导航有明确区别。

左侧显示实际产品与功能组、现有页面入口和可核验上下文；不虚构项目名、分支、Owner、草稿数量或环境健康。深链按最长路径选择组/页面，不默认跳回第一页；全局 side/top 偏好继续有效。390px 下页面导航折叠为可访问按钮，展开后自然转移键盘焦点，关闭/选择后返回可见控件。

| 功能域 | 原型主导航与现有路由 |
| --- | --- |
| 总览 | `/ontology` |
| 业务模型 | 模型工作台 `/ontology/model/graph`、对象类型、关系类型；接口/公理作为高级语义入口，旧 `/ontology/model/*` 深链保留 |
| 数据接入 | 来源绑定/对象映射、本体血缘沿用 `/ontology/data/*`；真实连接只引用已有连接资源 |
| 业务动作 | 动作类型沿用 `/ontology/logic/actions`；函数和编排作为高级实现入口 |
| 变更发布 | 变更草稿、版本与发布、导入导出沿用现有 `/ontology/governance/*` |
| 运行与质量 | 同步任务、模型校验、动作执行、操作审计、使用量归组，保留原 URL；模型检查同义入口指向同一校验实现 |

对象浏览、ObjectSet、聚合、地图归入全局“对象探索”，继续现有 `/ontology/explore/*` URL。权限策略连接已有统一治理资源，不能复制权限事实。角色呈现依据已有真实身份/角色，不创造原型身份或在前端扩大权限；任何菜单裁剪都不是服务端授权。

功能归组保持现有产品范围。原型未展示但当前已存在的分析、地图、编排与使用量保留可达入口。planned 项继续不进入正式导航。

页面、选中资源、详情页签和查询视图进 URL；折叠、缩放、拖动位置与未提交表单属于界面状态。导航匹配采用最长路径，避免 `/ontology` 总览抢占所有子路由。浏览器刷新、前进、后退与旧路径重定向必须保持有效。

### 4.2 模型工作台与类型编辑

图、资源树和列表使用同一次真实 ObjectType/LinkType 读取。工作台内部采用左侧资源树、中央点阵卡片画布、右侧 Inspector、下方真实检查结果的布局；资源树支持同源筛选与类型选择，图与列表的过滤及计数一致。画布渲染类型卡片及属性摘要，关系端点来自 LinkType；不画实例关系。支持选择、键盘操作、拖动、缩放、适应画布和打开资源详情。拖动不写模型定义。

Inspector 展示选中类型的名称、标识、描述、主键、属性、关系和当前可核验状态，提供类型编辑、来源绑定与实例查询入口。底部校验区显示真实静态校验或模型检查结果；初始为“尚未校验”，不会使用原型固定错误计数。

类型详情采用资源切换列表、资源标题、属性表和局部页签，聚合概览、属性与约束、关系、来源绑定、业务动作、版本与影响。来源绑定读取真实 backing datasource；物化结果放入独立样本区，不把样本叫“数据源”。历史统一读取 listVersions；旧 overview/properties/links/datasources/history 深链映射到兼容视图。仅展示现有真实能力，新增类型及属性继续沿用现有字段校验、相似扫描、扩展元数据与破坏性确认。

对象跨页上下文由 URL 保存 `typeRef`、可用的 `changeRef` 和站内 `returnTo`；现有 `class` 查询参数继续兼容。来源、校验、发布、对象探索入口带入选中类型，返回时恢复原资源/页签/筛选。返回目标仅接受站内有效路径，URL 不保存令牌或敏感记录，后端仍以认证上下文复核访问。

已有直接保存与 WIP 暂存的语义保持可辨认；草稿保存使用现有未发布 WIP，发布由现有 apply/版本链路完成。WIP 当前按 RID 存储并记录租户/作者元数据，本轮不宣称作者专属可见性。未保存表单切换资源或关闭编辑器需要明确处理，不能静默丢失输入。BrowserRouter 的前进/后退允许导航，以身份/租户/资源隔离的会话内编辑副本、明确“未提交”提示及再次打开恢复处理输入；该副本不是服务端草稿，退出会话不可恢复，离开浏览器给出 beforeunload 提示。成功保存、主动丢弃、身份变更清除副本。新建/修改失败时保留编辑内容，403/409/422 使用真实错误信息。

### 4.3 数据映射

对象类型与来源绑定由真实列表选择。每行显示目标属性的业务名、机器标识、类型、主键/必填状态，并编辑其来源列；提交保持 `field_mapping` 的属性 RID → 列名语义。防止重复目标、空来源等无效输入。

完整表单沿用来源名称、kind、table、pk_column、dsn_env、priority 等后端已有字段。凭据引用使用已有环境键，不在前端收集或保存数据库口令。

水位列以真实 DTO 和契约为准：现行 BackingDatasourceCreate/后端声明 DTO 未提供 `ts_column` 入参，不能把原型的水位编辑保存按钮直接搬入正式平台。显示服务端实际配置；本次不扩大后端声明语义。

样本区读取真实物化结果，标明来源与获取状态；预览不启动同步。全量/增量同步继续走现有受控接口，显示真实执行结果，失败不转成成功进度。未保存映射不能触发相关同步操作；切换类型前处理未保存输入。源字段元数据/源样本预览若无现有契约则不伪造下拉；当前来源列可按已有声明编辑，接口缺口单独登记。

### 4.4 发布与治理

草稿审阅、校验、影响评估、确认、发布结果和历史在界面上组成可理解的步骤，底层继续使用 ADR-0080/0082 的现有能力。每一步关联具体类型与草稿；修改输入或切换资源使旧校验/评估失效，失败保留草稿与可重试状态。

版本页与类型历史均读取 `listVersions` 的不可变快照，以 checksum 判定当前生效版本。用名称和版本选择替代普通用户手填 RID 的主要操作；高级标识仍可查看。

破坏性确认、服务端冲突、默认保留数据、迁移评估/执行与结果核对不退化。模型发布与实例迁移是各自明确的动作；模型回滚只恢复模型定义，不承诺实例恢复或外部副作用补偿。该前端改造不提前实现路线图 R2–R6 的后台能力。

### 4.5 全平台现有页面

总览、关系、接口、约束、对象浏览、ObjectSet、动作、函数、执行记录、安全、审计与导入导出使用统一页头、容器、留白、表格与状态样式。总览强调继续建设、阻断项与可操作下一步，不推断后台没有返回的负责人/健康状态。沿用真实数据与业务操作；动作审批配置、函数沙箱测试等原型演示如无对应现有能力，不新增虚构按钮。

工作台采用实际汇总、待办与继续工作区域；应用和员工目录采用名称、真实状态、描述、现有配置/运行入口组成的卡片或列表。知识与集成、治理与管理沿用现有资源列表和详情，但使用相同功能组、页面导航、页头和可操作的加载/错误状态。SuperAI 保留真实会话与任务链，按现有数据组织会话列表、对话和上下文，窄屏可切换；原型示例指令不能假装已调用模型或工具。所有 active 页面按已登记路由形成覆盖清单，额外原型页面只有能映射到既有真实能力时才提供入口。

区分 empty、forbidden、unavailable、partial、stale：已成功读取的空数据是 empty；403 是 forbidden；服务失败是 unavailable；独立辅助面失败是 partial；保留旧读取数据时明确 stale。异步读取用取消或请求代次防止旧对象响应覆盖当前对象；设计状态、数据健康和业务状态分别命名。业务链中审批通过、受理和执行成功保持已有实际语义。

## 5. 视觉与组件约束

遵循新版原型的深色带标签入口栏、浅色顶栏/组栏/页面导航、浅灰工作区、白色面板、紫蓝强调色、细边框、有限圆角与低阴影。颜色和尺寸通过现有 Semi 主题包及应用令牌配置；不更换组件库，不新增 `.semi-*` 内部样式覆盖。新用户默认浅色；已持久化的用户主题、远端偏好与 dark/system 选项保持，浅/深主题都可读，状态同时有文字或图标。

复用 Semi、DataTablePro、EmptyState、PageHeader、ResourceDetailLayout、现有编辑器与现有 API client。共享页面模式优先统一全平台，必要页面局部适配；新增组件集中于功能组/页面导航、上下文/状态栏、模型资源树与画布、资源 Inspector 和映射布局，避免把业务状态写进全局壳。

桌面主验收尺寸为 1440px 和 1920px；1024px 下收缩 Inspector 与导航，390px 下工作区导航通过按钮展开，内容局部横向滚动，页面无文档级溢出。窄屏提供资源访问与基本操作，复杂建模仍面向桌面。

## 6. 研发单源与集成

实施前在 [ADR-0069](../../active/decisions/ADR-0069-ontology-ia-v2-workspace-navigation.md) 和 [IA v2 规格](../../active/specs/2026-09-18-ontology-ia-v2-design.md) 增补本次导航呈现决定，明确覆盖 2026-09-24 的横向呈现附录，并保留历史与路由成果；同步文档入口。

模型、草稿、版本、迁移及权限遵循 [ADR-0080](../../active/decisions/ADR-0080-ontology-draft-and-version-mechanism.md)、[ADR-0082](../../active/decisions/ADR-0082-ontology-migration-plan.md)、[ont.yaml](../../../mate-platform-backend/contracts/openapi/services/ont.yaml)、[产品模块规格](2026-09-01-metaplatform-product-modules-design.md) 和 [硬规则矩阵](../../active/governance/HARD-RULES-MATRIX.md)。产品模块规格的“待书面评审”和总体架构的条件性状态保持原文口径。

复用现有 API。若本次新增调用需要同步未登记的既有端点，先按实际 DTO/行为补齐契约与调用断言，再接界面；不发明新路由、审批策略或数据迁移语义。已有业务模型冲突按 AGENTS 停止受影响实现并先修订单源。

真实首载验证定位到既有登录调用遗漏：当前独立 Keycloak 对未请求 `openid` 的 password grant，其 userinfo 返回 403，IAM 登录因此返回空用户 ID；请求 `openid` 后同一真实账户 userinfo 返回 200 和稳定 subject。补齐现有登录调用的身份读取范围，使已有 UserInfo/用户 ID 数据链可用，不增加角色或权限，不修改签名验证、租户守卫、认证持久化。保留后台最佳努力的 HTTP 200/SUCCESS、DTO、令牌与错误处理流程；当 userinfo 没有 subject 时，dashboard 与 IAM 一样返回空 ID，移除由用户名生成 `u-{username}` 的替代身份。UI 只在获得有效用户 ID 与令牌后建立个人登录会话；缺少 ID 明确提示重试，编辑缓存不以空 ID 共享或伪造 ID。用户信息接口故障期间，依赖替代 ID 的旧 dashboard 消费者需要重试登录，正常 provider 身份仍兼容。该修复是现有主题加载和按身份隔离编辑输入的前置条件，按 Task 10 单独实现/评审/实际取证。

在当前隔离工作树按“文档/ADR → 契约（必要时）→ 失败测试 → 前端实现 → 独立验证证据”提交。导航、types、共享壳等核心文件串行整合；四段渐进接入，完整目标覆盖全平台现有页面。
