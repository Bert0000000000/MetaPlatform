# 逆向建模发布后数据同步实施计划

状态：功能已实施并完成本地工程验证；最新后端调整已重启加载。详见[验收记录](../../acceptance/2026-10-11-modeling-data-sync.md)，业务验收及 CI 另行登记。

## 目标与边界

把现有逆向建模的数据同步能力整理为发布后的独立可选步骤。使用已上传的 Excel、已审核映射和平台原生同步管道，正式实例统一由对象浏览查看。用户可以只发布本体，稍后再同步。

遵循 [ADR-0083](../../active/decisions/ADR-0083-data-driven-modeling-phase1.md)、[草稿与版本 ADR-0080](../../active/decisions/ADR-0080-ontology-draft-and-version-mechanism.md)、[迁移 ADR-0082](../../active/decisions/ADR-0082-ontology-migration-plan.md)。不另建实例库，不自动补业务规则，不自动发布或同步用户数据。

## 已有能力

- FromDataPage 的发布结果下已有折叠的 DataReadiness 和同步按钮，尚不易发现。
- POST /ont/v2/modeling/sources/{ident}/sync（ontSyncModelingSource）会重新检查数据，并检查发布计划匹配和原生模型是否变化。
- ingestion.sync 把 Excel 暂存为受控来源，使用原生 backing datasource 同步生成对象，再写入原生关系实例。
- 对象浏览使用 listIndividuals 读取正式实例；对象映射页支持来源配置以及全量、增量同步。
- 当前同步分类型、分关系执行，不是跨整个来源的原子事务；失败可能保留已成功写入的数据，界面必须如实呈现。

## 产品流程

数据与建模范围 → 候选本体审核 → 校验与预览 → 本体发布 → 数据同步（可选）。

发布成功后显示“同步本次数据”和“稍后同步”。不自动执行写入。第五步是当前来源的检查、执行及结果入口，长期接入管理仍使用原生数据接入页面。

第五步包含：

1. 同步范围：来源名称、已发布对象类型、映射来源表及来源行数。当前版本按本次已发布范围整体同步，不增加临时勾选类型或跳过错误行功能。
2. 数据检查：按对象与原因合并阻断项，展示影响数量、示例和处理入口；区分身份缺失、同身份属性冲突、映射问题和关系定位问题。语义提醒与数据阻断分开展示。
3. 同步预览：数据检查通过后展示预计对象及关系数量；来源行数与去重后的对象数明确区分。检查失败时不把未计算数量显示为 0，不显示误导性完整预览。
4. 执行状态：未检查、检查中、存在阻断、可同步、同步中、成功、失败或结果待核实。只显示真实阶段和数量，不提供虚构百分比。
5. 同步结果：按类型显示实际同步数量及失败信息，关系显示已完成数量；提供“查看实例”“查看数据映射”“查看同步状态”入口，并携带 typeRef、sourceRef、returnTo 等适用上下文。

按钮禁用时给出具体原因：未发布、存在未保存修改、数据检查有阻断、发布定义漂移，或正在执行。用户刷新或重新进入时回读真实状态，不自动重发同步请求。

## 实施顺序

### 1. 页面分步与入口

- 将折叠的数据检查、同步内容从发布步骤提取为独立组件及第五步。
- 保留现有审核、校验、发布行为，更新步骤导航、进入条件、历史来源恢复和返回入口。
- 同步为可选步骤，“稍后同步”不触发写入；已有成功发布但没有同步的来源可直接进入检查。

### 2. 检查报告与问题定位

- 复用 DataReadiness、数据校验及 compile_graph 的计算结果，梳理独立检查是否需要新增只检查数据的接口；不通过再次发布刷新数据报告。
- 若现有响应不足，再扩展 ont.yaml 契约，定义来源修订和配置标识、报告完整性、预计数量及分组问题，前后端同步实现。
- 修订号或配置变化立即使旧报告失效，执行前仍由服务端重新检查，不能只依赖前端按钮状态。
- 映射问题定位到逆向映射详情或适用的原生映射页；身份/结构问题定位到对象详情。已发布身份变更走平台修订/迁移流程，不解锁已发布身份。
- 来源值问题展示原表与行号供用户修正；本期不新增在线 Excel 行编辑器。重传数据沿用现有接入流程，不伪装成原来源可直接替换。

### 3. 同步状态与失败恢复

- 复用原生数据同步与实例关系写入，不建立平行导入实现。
- 校验全部通过后才允许启动当前范围同步；这只是写入前检查，不承诺运行时全部原子成功。
- 核实对象及关系重复执行的幂等性，展示已成功部分；重复同步默认保留来源中缺失的旧实例，不做自动删除。
- 核实运行状态的可回读性和中断识别；如长请求容易超时，补充持久任务状态与安全查询机制，避免前端超时被显示为“未写入”。仅在真实终止后允许重试。
- 验证 Excel 受控来源配置可用；配置不足时给出可理解的错误，详细技术信息保留在诊断信息中。

### 4. 原生页面衔接

- 成功后按类型跳转对象浏览，验证实例数量、属性及关系可读。
- 在原生映射页能够识别逆向建模声明的 excel-modeling 来源。
- 不直接把通用映射编辑当作逆向方案修订：说明两者的保存边界，检查修改后的再同步是否会被旧逆向配置覆盖，必要时阻止并提示返回对应流程核对。

## 验收标准

- 仅发布本体不会新增实例；稍后同步、浏览预览和跳转均无数据写入。
- 未发布、有阻断、报告过期或原生定义已变化时，服务端拒绝同步。
- 独立测试来源通过检查后，可生成真实对象和关系，在对象浏览中读取到预期结果。
- 相同来源重复同步不重复生成同身份对象或相同关系，不自动删除缺失数据。
- 模拟中途失败、请求超时、刷新和恢复，界面如实呈现已有写入，不错误宣称全量回滚或完成。
- 正常数据及身份缺失、身份冲突、子类、复合身份和无效关联等场景有针对性测试。
- 前端类型检查、构建与相关单元测试通过；后端使用独立数据库及浏览器用例验证真实链路，不改动用户来源或共享业务实例作测试。

交付顺序：步骤和页面 → 报告及必要契约 → 同步恢复与跳转 → 独立端到端验收。工程验证与业务验收分别记录。
