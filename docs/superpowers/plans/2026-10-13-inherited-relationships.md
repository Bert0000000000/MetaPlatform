# 子类适用父类关系实施计划

依据：产品 1.1 规格 2026-10-13 用户授权补充；承接用户“补齐一下”的执行授权。

目标：同租户合法后代可使用父类关系，保留原定义、方向、基数和安全约束；图及 inspect 能解释继承适用关系。

- [x] 文档与契约：明确方向性、传递继承及失败边界；inspect 增加可选声明端点信息。
- [x] 后端红绿测试：HTTP、内存、真实 PostgreSQL 覆盖两端多级继承及拒绝反向、无关类、跨租户；共用继承判断，PG 事务内链锁。
- [x] 查询与同步：inspect 返回继承适用关系；父类实例查询包含子类，原生同步复用同一写入入口；既有真实建模同步回归通过，新增后代端点 HTTP/仓库回归通过（未单独新增后代端点 Excel 同步端到端场景）。
- [x] 前端红绿测试：使用完整目录计算关系适用性，详情区分直接/继承；选中子类图上线注明继承适用，点击原定义。
- [x] 独立数据库和浏览器：必需六组数据库回归实际执行，隔离端口检查实际共享组件页面（固定数据浏览器烟测，不等于真实服务端端到端验收）；类型检查、构建及静态检查。
- [x] 代码复审、记录验证证据、推送 PR；部署与业务验收状态单独列出。

文件边界：kernel ontology 新增关系端点继承 helper；in_memory.py、v2_kernel/api.py、pg_repo.py 使用同一规则。前端 graph 新增 applicableRelationships helper，由 SchemaGraphCanvas 和 ModelInspector 消费。保留服务、现有数据库及工作树，不使用清理或重置。
