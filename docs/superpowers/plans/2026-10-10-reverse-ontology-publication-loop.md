# 逆向本体发布闭环实施计划

**Goal:** 逆向任务以审核后的原生本体发布为完成标准；数据质量独立限制可选同步。
**Architecture:** 仅调整 modeling 包与独立前端入口。新增本体结构校验，原有完整数据校验及原生发布、WIP 保护、指纹和同步语义保留。嵌套数据报告保存于现有 source.validation JSON，无数据库迁移。
**Tech Stack:** FastAPI/Pydantic/PostgreSQL，React/Semi UI，pytest/Vitest/Playwright。

## Constraints
- 不修改正向建模及原生内核主链路，不替用户确认或发布真实候选。
- 数据错误不阻断结构发布；结构/继承/原生冲突继续阻断。同步前必须重新执行完整数据校验。
- 平台技术主键与业务身份区分；不自动猜测复合身份或填编号。保留既有无业务身份的明确来源记录策略，继承继续要求一致身份。
- 以已接受 ADR-0083 和本计划为逆向模块边界，原生接口保持不变。

## Tasks
- [x] 1. 更新 ADR 和 OpenAPI：本体报告 scope=ontology，嵌套 dataValidation/canSync、分组问题和身份数据证据。
- [x] 2. 先写失败测试；实现结构/数据独立校验、重复问题汇总、发布门禁和同步独立门禁。验证空编号可发布结构而不可同步，结构错误及继承冲突仍阻断。
- [x] 3. 重构四步主流程为数据范围→候选本体审核→本体校验与接入预览→本体发布与验收。同步变为发布后的可选折叠区；展示定义数量/原生链接和独立数据限制。
- [x] 4. 跑 core/AI、真实非特权 PG、前端单元/类型/构建和浏览器闭环。对真实问题候选只重校验不发布；记录当前结果及限制。

## Acceptance evidence

见 [本地工程验收](../../acceptance/2026-10-10-data-modeling-phase1.md) 的闭环调整记录：157 条核心/AI、19 条发布同步 PG、123 条原生 PG、16 条前端单测与 5 条浏览器用例通过，类型检查和构建通过。真实来源仅重新校验，8 个原生冲突仍要求人工处理，未替用户发布。
