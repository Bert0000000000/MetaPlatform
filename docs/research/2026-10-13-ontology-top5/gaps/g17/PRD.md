# G17 PRD：反模式检查加载中不得显示假通过

2026-10-13 · P1 · web 应用增量 · 有效工作预算60分钟 · 待实施。
无本批其他工单前置依赖，无新增API、数据库迁移或外部服务。

## 问题与源码依据

建模者打开模型校验或重新检查时，应能判断本轮检查是否完成。基线 dc8980d3e129e94f0bc55190705ede7cbe304ba0 的 metaplatform-frontend/apps/web/src/pages/ontology/model/validation/ModelValidationPage.tsx 初始化 findings=[]、loading=true，但内容仅按error/findings.length渲染，响应前可出现“✓ 未发现反模式”，标题提前显示0项。重查时旧结果也容易被当成本轮结果。此为源码状态分支判断，未冒充当前云端浏览器复现。

对标Protégé的计算状态与结果来源分离原则；本平台OntologyGraphView已有generation/cleanup模式可参考。源链接及对标细节见../../AUDIT.md。

## 目标和非目标

只修反模式lint的加载、错误、成功状态及必要请求生命周期保护。只有本次请求成功返回[]后，才能显示未发现。SHACL/G07、公理/G09、后端规则、完整OWL推理不在范围内，不新增全局状态库。

## 交互与文案

| 状态 | 可见反馈 |
|---|---|
| 首次pending | “正在检查反模式…”；不显示零项成功、绿色通过或空列表成功图 |
| 重新检查pending | “正在重新检查反模式…”；隐藏旧结果，按钮busy/disabled，不并行重复提交 |
| 成功0项 | “未发现已检查规则覆盖的反模式”；标题显示0项，不宣称整个本体正确 |
| 成功N项 | 展示本次实际数量、发现项及建议 |
| 失败 | “反模式检查读取失败”、可理解原因及重试；没有成功结论 |
| 离开/过期响应 | 不更新失效页面或覆盖新请求结果 |

渲染顺序优先loading→error→本次成功结果。沿用现有Semi UI，加载区使用合适的aria-busy/status，避免重复播报。只消费lintAntiPatterns()，没有写入、发布、自动修复或新扫描行为，保留原租户权限链路。

## 验收与独立测试

- [ ] deferred promise保持首次pending：无假通过，加载反馈可见。
- [ ] []/非空结果分别只有成功完成后显示真实结果。
- [ ] 重查pending不把旧结果当本轮，快速重复点击不并行提交。
- [ ] 首次失败、成功后重查失败、重试成功均状态正确。
- [ ] 卸载及迟到响应不覆盖失效状态，busy能结束，SHACL原行为回归。

组件测试覆盖慢/错/重试；Playwright实际进入/ontology/model/validation验证状态，使用真实lint端点做只读成功冒烟。网络拦截/故障注入与真实端点结果分开记，不能声称故障注入证明服务器稳定。
