## 1. 待引入组件清单与协议分析

### 1.1 RAGFlow（重点：AGPL-3.0）

| 维度 | 内容 |
|---|---|
| 协议 | **AGPL-3.0**（网络服务强传染） |
| 引入方式 | 服务级调用（**不修改源码**） |
| 部署方式 | Docker / K8s（内部部署） |
| 关键 AGPL 条款 | **Section 13 - Remote Network Interaction** |

**AGPL-3.0 条款拆解**（对**你**的场景）：

| 条款触发条件 | 我方做法 | 是否触发 |
|---|---|---|
| 修改源码并分发 | 不修改 RAGFlow 源码 | ❌ **不**触发 |
| 提供网络服务（未修改） | 作为内部工具运行 | 🟡 灰区（见下） |
| 衍生作品 | 我们的代码与 RAGFlow 独立 | 🟢 隔离清晰 |

**Section 13 灰区分析**：
- AGPL-3.0 主要针对"修改后的网络服务"
- 服务级**未修改**使用 RAGFlow 是否构成"提供 Program as a service"——**社区有争议**
- 多数法律意见认为：未修改的服务级使用 + 完整 LICENSE 保留 = **较低风险**
- 触发高风险：修改 RAGFlow 后对外提供服务

## 2. 风险自评决策矩阵

### 2.1 RAGFlow 风险等级评估

**请逐项打勾**：

#### 场景 1：内部使用（不商业化）
- [ ] 我仅在企业内部使用 RAGFlow
- [ ] 不对外提供服务
- [ ] 不修改 RAGFlow 源码
- **风险等级**：🟢 **低**
- **结论**：可直接使用，无需额外措施

#### 场景 2：作为 ToB 产品一部分（最可能的场景）
- [ ] 我的产品提供给企业客户
- [ ] RAGFlow 作为产品的"内部组件"运行
- [ ] 用户**不直接**访问 RAGFlow API
- [ ] 我**不修改** RAGFlow 源码
- **风险等级**：🟡 **中**（协议争议区）
- **缓解措施**：
  - [ ] 完整保留 RAGFlow LICENSE（含版权声明）
  - [ ] 在产品文档 / About 页致谢 RAGFlow
  - [ ] 不在产品中"宣传"使用 RAGFlow（避免引起注意）
  - [ ] 准备"应急方案"（如法务要求，可下 RAGFlow 改为 Java 重写）

#### 场景 3：作为 SaaS 对外提供（高风险）
- [ ] 我以 SaaS 形式对外提供服务
- [ ] 用户**直接**调用 RAGFlow API
- [ ] 用户感知 RAGFlow 存在
- **风险等级**：🔴 **高**
- **建议**：
  - [ ] **不推荐**用 RAGFlow
  - [ ] 改用 Java 自研（参考 `2026-07-27-rag-graphrag-best-solution.md` 历史方案）
  - [ ] 或采购 RAGFlow 商业许可证（联系 InfiniFlow）
  - [ ] 或用 LightRAG 替代
